## Context

The agent runs on the owner's mac as the owner's user. It shares the user, the network stack, localhost, and a home that persists. srt keeps it in with a list of rules on top of that shared host, and each gap in the list has needed its own patch:

- Incoming: with `allowLocalBinding: true`, srt allows `(allow network-inbound (local ip "*:*"))` (srt 0.0.81 `dist/sandbox/macos-sandbox-utils.js:951` to `:953`). The guard in `../THREAT-MODEL.md` U7 is the macOS firewall, and on this mac `socketfilterfw --getglobalstate` printed `Firewall is disabled. (State = 0)` (2026-11-07).
- Localhost: every local service is reachable from the sandbox (`0004-no-local-binding.md`, "No direct localhost access from the sandbox", amendment 2026-11-03).
- Persistence: only the names in `config_names` are reset at a start (`host/bin/omp-arena` and `host/arena/init`, both removed); other loaders in the arena and in each clone outlast it.
- The macOS build check, the arena probe, and the socket folder rules exist only to keep srt's rules sound.

## Decision (proposed)

- **The box.** The agent runs in an Apple `container` VM with `--network none`: its own kernel, filesystem, and loopback, and no route off the box. One VM runs for all sessions, with no container per session inside it (`0015-box-layout.md`).
- **Vanilla omp inside.** omp runs in its default layout, on one home. Nothing in omp is moved or wrapped (`0015-box-layout.md`).
- **Doors.** The box reaches the host only through unix sockets that the host mounts in. Draft list: the gh-broker, and an egress socket to an allowlist proxy on the host. Model calls go through the egress door, and the host adds the gateway bearer there, so no secret enters the box.
- **Safety lives in the doors.** A box can be taken over and stay taken over across starts, so each door must hold against a hostile caller. What the gh-broker door allows (`gh-broker merge`, a finding of the 2026-11-07 re-check, which is not in the repo) is part of this design, not separate from it.
- **No spend limit at the model door** (owner decision, 2026-11-07). The owner's model logins are subscription OAuth only, with no paid API key, so a taken-over box cannot run up a bill. [inference] It can still use up the subscriptions' usage limits until they reset, or use the accounts in a way that breaks a provider's terms.
- **srt.** It stops being the sandbox and stays as the egress proxy.
- **Egress by name only** (owner decision, 2026-11-07). The proxy decides each HTTPS connection by the site's name and passes it through unopened, so the box needs no CA. This is srt's own HTTP proxy, `createHttpProxyServer` (srt 0.0.81 `dist/sandbox/http-proxy.d.ts:315`), run by a small host launcher on the egress socket: its `filter(port, host)` is the host allowlist (`:27`), and without `mitmCA` a CONNECT is "an opaque byte tunnel", "hostname-allowlisted via `filter`, but not content-inspected" (`:38` to `:51`). It is not exported from srt's index (`dist/index.d.ts`), so the launcher imports it by path and the srt pin holds it in place. Model calls are plain HTTP to the gateway (every `baseUrl` in the arena's `models.yml` is `http://<tailscale address>:4000`, read 2026-11-07), so the proxy replaces the box's placeholder bearer there with `mutateHeadersPlaintext` (`:101`). The owner's box run on 2026-11-07 showed all three paths through the socket door: an allowed HTTPS site, a refused one, and the bearer swap (Evidence). Why not open every connection: the box holds no GitHub or npm token, since pushes go through the gh-broker door, so a finer HTTPS check would stop only an anonymous upload to an allowed site, which U14 already accepts (`0001-accepted-risks.md`); it would cost a CA in git, npm, node, python, and curl.
- **Host services by name** (2026-11-07). The box never names a host service by a loopback or private address, because omp sends those past the proxy into the box's own loopback (Evidence). The box's `models.yml` and `OMP_AUTH_BROKER_URL` use names under `.internal`, which ICANN reserved for private use, such as `gateway.internal` and `usage.internal`; a real top-level domain such as `.ug` (Uganda) would resolve on the internet if a mapping were missing, and the proxy would then send the bearer in plain text to its owner. The proxy maps each name to an address on the host with `lookupFor` (srt 0.0.81 `http-proxy.d.ts:151`, type `DirectLookup`, `parent-proxy.d.ts:143`); the port stays the one the box asked for, so the box names the service's real host port. Its `filter` allows only the names it maps, each on its one port, and `lookupFor` refuses every other `.internal` name. A loopback test on 2026-11-07 (node, srt 0.0.81, in a session) showed this: `gateway.internal:8799`, mapped to `127.0.0.1`, reached the stand-in gateway with `Bearer probe-secret` in place of `Bearer placeholder`; the unmapped `usage.internal:8799` and the unlisted port `gateway.internal:4000` both got `403` "Connection blocked by network allowlist". The gateway stays where it is, on the tailscale address (owner decision, 2026-11-07: the tailnet holds only the owner's devices, and the owner watches it). The proxy maps `gateway.internal` to that address on port 4000, and `usage.internal` to `127.0.0.1` on port 18765, so the box holds neither address. [inference] Neither mapping is run yet. omp reads `PI_PROXY`, and git, npm, and the rest read `HTTPS_PROXY`, so the box sets both [inference: the two together are not run].
- **Host services on tailscale first** (owner decision, 2026-11-07). A host service listens on the tailscale address of this mac wherever it can, and on loopback only where a feature needs loopback, such as omp's `/stats` dashboard on `127.0.0.1:3847` (`0004-no-local-binding.md`, "Amendment 2026-10-31: loopback allowed"). The owner watches the tailnet, and it holds only the owner's devices, among them the box of the inference engine. The box itself never joins the tailnet: it has no network, and the egress proxy on the host dials each service for it, at whichever address the service listens on. Not yet decided: whether the auth broker (`127.0.0.1:8765`) and the usage broker (`127.0.0.1:18765`) move to the tailscale address; until then the proxy maps `usage.internal` to `127.0.0.1:18765`.
- **Kept from underground:** the gh-broker, the auth broker and gateway, the merge gate, setup with its pins, and the backup.
- **Gone once built:** srt as the sandbox, the wrapper's srt settings, `host/arena/init`, `config_names`, the macOS build check, and `scripts/probe-arena.sh`.

## Evidence

Owner runs on this mac, 2026-11-07, `container` 1.7.1 (`container --version`: `build: release, commit: a15b460`), kernel from the recommended Kata 4.3.1 release:

- An `--internal` network is not enough. On `container network create --internal ugbox`, the box had `default via 192.168.128.1 dev eth0`. A TCP connect to `1.1.1.1:80` timed out, but the mac's gateway address `192.168.128.1:8765`, its wifi address `<wifi-ip>:8765`, and the auth gateway `<tailscale-ip>:4000` were all `open`.
- `--network none` has no route. `ip addr` showed only `lo` (`127.0.0.1/8`, `::1/128`), `ip route` printed nothing, and connects to `1.1.1.1:80` and `192.168.128.1:8765` failed with `OSError`.
- A socket door works with no network. With `-v /tmp/ug-probe.sock:/door.sock` and `--network none`, the box sent `ping`; the host listener printed `host got b'ping'`, and the box printed `b'door ok ping'`.
- A reply can be lost when the host closes at once. A host listener that sent and closed at once gave the box `b''`; with a one-second wait before the close, the reply arrived. [inference] The socket forwarding drops data on a fast close. The real gh-broker must be tested through the door.
- The `container` docs document no `none` network on `container run`; the only restriction they show is `container network create --internal`, "Restrict to host-only network" (`docs/command-reference.md`, main branch, read 2026-11-07). `--network none` works in 1.7.1 but is not documented, so the start must check for it.
- The egress door works from a box with no network. On the host, srt 0.0.81 `createHttpProxyServer` listened on `/tmp/ug-egress.sock` with a `filter` that allowed `registry.npmjs.org:443` and `127.0.0.1:8799` (a stand-in gateway), and a `mutateHeadersPlaintext` that set the bearer for `127.0.0.1`. In a `--network none` box with the socket mounted, a Python relay on `127.0.0.1:3128` forwarded to it. Results: `https://registry.npmjs.org/` gave `200` through an unopened CONNECT, with the box's own TLS; `https://example.com/` gave "Tunnel connection failed: 403 Forbidden"; `http://127.0.0.1:8799/`, sent with `Bearer placeholder`, gave `200`, and the stand-in gateway printed `authorization: Bearer probe-secret`. The proxy logged `filter registry.npmjs.org 443 allow`, `filter example.com 443 deny`, `filter 127.0.0.1 8799 allow`. The refusal arrived whole, so the fast-close loss above did not hit it (owner run, 2026-11-07).
- omp skips the proxy for loopback addresses and uses it for a name. Run on 2026-11-07 in a session: the pinned omp 18.13.2 (`omp-darwin-arm64`), `omp -p hi --no-session --no-tools --no-lsp` with its own `HOME` and a `models.yml` with one provider, a logging proxy on `127.0.0.1:3130`, and a logging upstream on `127.0.0.1:8799`. With `PI_PROXY` set, a model call to `http://127.0.0.1:8799` went direct, for both `api: openai-completions` (`DIRECT POST 127.0.0.1:8799/v1/chat/completions`) and `transport: pi-native` (`DIRECT POST 127.0.0.1:8799/v1/pi/stream`); to `http://gateway.ug:4000` it went through the proxy for both (`PROXY POST http://gateway.ug:4000/v1/chat/completions`, `.../v1/pi/stream`), and so did `http://<tailscale-ip>:4000`. `OMP_AUTH_BROKER_URL=http://127.0.0.1:8799` went direct (`DIRECT GET 127.0.0.1:8799/v1/snapshot`); `http://usage.ug:18765` went through the proxy (`PROXY GET http://usage.ug:18765/v1/snapshot`). The run used `.ug` test names; the design uses `.internal` (Decision). This matches omp's docs: "Loopback, link-local, private-range (`10/8`, `172.16/12`, `192.168/16`), and `NO_PROXY` targets always bypass" (omp `docs/environment-variables.md`, lines 174 to 175, read 2026-11-07). The box runs a Linux omp, so this has to be checked again on that pin. Two more facts from the same run: when the auth broker does not answer, omp stops ("will not fall back to local credentials automatically"), so the usage door must be up before omp starts; and at each start omp tried CONNECTs to seven catalog hosts (`catalog.stencil.so`, `coding-intl.dashscope.aliyuncs.com`, `hyper.charm.land`, `api.commandcode.ai`, `api.kilo.ai`, `api.venice.ai`, `zenmux.ai`), which the allowlist will refuse.

## Open

- The doors against a hostile caller: the gh-broker verbs and the allowlist.
- The relay inside the box: omp, git, and npm reach a proxy by host and port (`HTTPS_PROXY`), not by a socket, so the image needs a TCP-to-socket relay on the box's loopback.
- What persists, where it lives, and what the backup covers: `0015-box-layout.md`, "Decision (proposed)" ("One home", "Rebuild") and "Open".
- The image and how a session starts: `0015-box-layout.md`, "Open".
- Decided 2026-11-07: the host code runs from a copy that setup installs (`0015-box-layout.md`, "The mac runs an installed copy of underground").

## Rejected

- An `--internal` network alone: the box reaches every service on the mac that listens on all interfaces (Evidence).
- An `--internal` network plus a pf rule that drops the box's subnet: it works without an undocumented mode, but it is a host rule to keep loaded, and reading pf rules needs root at each start. Keep it as the fallback if `--network none` goes away.
- colima and Docker Desktop: both reach the mac's localhost by default (`host.lima.internal`, `host.docker.internal`), and Docker's `-p` listens on every interface. [inference] From memory, not read in their docs.
- Patching srt to bind loopback only: srt's comment says Seatbelt's `localhost` matches the any-address (`macos-sandbox-utils.js:943` to `:947`), so it may close nothing.

## Cost

- A Linux image to build and pin, and a Linux omp.
- A VM for the box: memory and start time. Measured on 2026-11-07: a box starts in under a second, and the cost of the VM on the mac is not measured (`0014-session-containers.md`, "Evidence").
- `--network none` is undocumented in `container` 1.7.1, so an update can remove it; the start must refuse a box that has a route.
- Tailscale is wider than loopback: every device on the tailnet can reach a service that listens there, and a loopback service only this mac. If the auth broker moved to the tailscale address, its bearer would be the only thing that keeps every tailnet device from the provider logins.
