# The login user: no login, key, or omp that the owner's user can use

Date: 2026-11-08. Status: built, not yet run on the owner's mac. Owner decision in chat, 2026-11-08: "i don't want to be able to start vanilla omp sessions and even if it starts, it should have no logins and keys and crippled." The owner said yes to this plan on 2026-11-08. Amends `0017-one-omp-binary-and-no-ug-folder.md` (the ug-auth profile, and vanilla omp by full path).

## Context

- A file that the owner's user can read, any program of the owner's user can read. So the ug-auth profile is no wall: vanilla omp with `--profile ug-auth` gets every login (omp `docs/config-usage.md`, line 78, read 2026-11-08). `0012-pinned-omp-and-setup.md` (Rejected) said the same: only a second macOS user stops it.
- The owner can run the one omp binary: it is mode 555 (`ls -la /Library/Underground/omp/18.18.1/`, 2026-11-08). Tern also keeps omp copies that the owner can run (`0012`, Context).
- The owner can read the gateway bearer: `/Library/Underground/config/models.yml` is root-owned and `go-w`, not `go-r` (`stage_config`, `host/bin/ug-agent-setup`). With it, any omp reaches every served model.
- Copies of the logins that the owner can read, counted with `select count(*) from auth_credentials` (owner runs, 2026-11-08): the live store `~/.omp/profiles/ug-auth/agent/agent.db` has 13, the old copy `~/.omp/profiles/ug-auth/from-dot-omp/agent/agent.db` has 12, and the owner's `~/.omp/agent/agent.db` has 0. For a week the logins also sat in `~/.ug/host/auth`, so they can be in Time Machine, APFS snapshots, the restic repo, and the Trash.

## Decision

1. **A login user, `ugauth`.** Standard, hidden, never an admin, shell `/usr/bin/false`, home `/Users/ugauth` at mode 700, with `.omp` and `logs/` in it. `ug-agent-setup` makes it with the same code as `ugagent` (`make_user`). omp runs there on its default profile; `OMP_PROFILE` goes.
2. **The login services are LaunchDaemons.** The auth broker, the auth gateway, and the usage broker run from `/Library/LaunchDaemons` with `UserName=ugauth`, because a user that never logs in has no `gui/<uid>` domain for LaunchAgents. Setup boots out and deletes the three owner LaunchAgents, and waits until launchd no longer lists them. Setup handles the services in that order, one at a time (`ug_ensure_service`, `host/lib/ug.bash`; the owner's gh-broker and backup jobs in `ug-setup` use the same code). It leaves a service running when the fingerprint of what the service reads at start equals the one saved after its last good restart, launchd lists it, and it answers its health route. Otherwise it boots the old one out, loads the new one only after `launchctl print` no longer finds the old one, and saves the fingerprint only once the new one answers, so a run that stops halfway leaves no fingerprint and the next run restarts that service. The fingerprints cover the rendered plist, the omp pin's `omp.sha256` (the plist names the version folder), the node binary for the node services, their code files, and the bearer tokens that `auth-broker serve` and `auth-gateway serve` read once at start (omp `packages/coding-agent/src/cli/auth-gateway-cli.ts`, `runServe`, v18.18.1, read 2026-11-08). The login store, the addresses file, and the gh-broker app config are read per request and stay out. Before this, setup loaded each service right after its bootout. On 2026-11-08 the 14:33 run gave `EADDRINUSE` restarts of the broker (`/Users/ugauth/logs/auth-broker.log`, owner run), and the 15:08 run left the gateway unloaded and never restarted the usage broker (the usage broker kept its process, and the files of the later steps kept their 14:33 times, `stat` and `ps`, 2026-11-08).
3. **Code that runs as `ugauth` is root-owned.** The usage broker's code goes to `/Library/Underground/usage-broker` and the addresses file to `/Library/Underground/addresses`, root-owned. Since 2026-11-10 both are in `/Library/Underground/code` (`0024-state-over-incident-lists.md`). A copy in the owner's data folder would let any owner process change code that runs with the logins. The usage broker reads the gateway token from `/Users/ugauth/.omp/auth-gateway.token`. `auth-broker token` and `auth-broker serve` loaded no extension and no hook from a planted `~/.omp/agent/extensions` and `hooks/pre`, while a prompt loaded both (marker files, run as `ugagent`, 2026-11-08). `auth-gateway serve` was not run that way.
   Changed 2026-11-09: the usage broker ran on `/opt/homebrew/bin/node`, and the three services had `/opt/homebrew/bin` first on `PATH`. The owner owns both, so an owner process could change code that runs with the logins. The usage broker now runs on the pinned omp (`ProgramArguments` and `BUN_BE_BUN`, `host/agent/com.underground.usage-broker.plist`), the `PATH` is `/usr/bin:/bin`, and setup refuses to load a service that names a program, a folder, or a `PATH` entry which a user other than root or `ugauth` owns or can write, by mode or by an access rule (`ug_trusted_daemon`, `host/lib/ug.bash`). No login service is a node service now, so no fingerprint of one covers the node binary (decision 2): the usage broker's covers `omp.sha256` (`inputs`, `host/bin/ug-agent-setup`). The owner's gh-broker kept node in its fingerprint until it moved to the pinned omp (`0025-agent-input-runs-with-least-rights.md`).
4. **The owner cannot run omp.** The binary is `root:ugomp`, mode 550, and the group `ugomp` holds `ugagent` and `ugauth` only; setup takes the owner out of it. `agent-start` and the gh-broker client run as `ugagent`, so they keep working. Setup's own check of the pin reads the root-owned `omp.sha256` instead of the binary. `scripts/gh-broker-app-wizard.sh` no longer runs the gh-broker client as the owner; it tells the owner to start `omp`, whose start runs `gh-broker sync` first.
5. **The owner cannot read the bearer.** `/Library/Underground/config` becomes `root:ugagent`, folders 750 and files 640. `agent-start` copies it as `ugagent`, so sessions keep it.
6. **The backup leaves out the agent's config.** `/etc/sudoers.d/underground-backup` lets the owner run `/Library/Underground/bin/agent-home-tar` with no password, and it tarred all of `/Users/ugagent`, including `.omp/agent/models.yml` with the bearer. The helper now excludes every `config-names` entry under `./.omp/agent`, read from the root-owned `/Library/Underground/config-names` (now `/Library/Underground/code/config-names`), because `agent-start` copies them back at each start (`config-names`, `host/agent/agent-start`). `tests/host/ug-agent.test.ts` checks that a bearer in `models.yml` is not in the stream. Older snapshots hold the old bearer, which the new one in item 8 kills.
7. **`ug-auth` uses sudo.** `ug-auth auth-broker login <provider>` runs `sudo -u ugauth -H /usr/bin/env -i HOME=/Users/ugauth … <omp> auth-broker …` from `/`, so each login asks for the owner's password. `auth-gateway` commands also get `OMP_AUTH_BROKER_URL`. `ug-auth key <NAME>_API_KEY` stores an API key for a provider whose login offers none, such as `ANTHROPIC_API_KEY`: the login user's shell reads the key hidden and passes it in the environment to `auth-broker migrate --from-local --include-env`, which uploads it to the broker (a throwaway broker printed `uploaded [env] anthropic (api key)`, 2026-11-08).
8. **New logins, old ones revoked: required.** The login user starts with an empty store and a new gateway bearer, so model calls fail until the owner logs in again. The owner logs in to every provider with `ug-auth`, then signs out of the old sessions or revokes the old refresh tokens at each provider, so every old copy is dead, found or not. Then the owner deletes `~/.omp/profiles/ug-auth` (the live store and `from-dot-omp`) and empties `~/.Trash/ug-old`. Setup warns while `~/.omp/profiles/ug-auth` exists.
9. **Setup checks the walls as the owner.** It fails if the owner can run the binary, read `/Library/Underground/config/models.yml`, or list `/Users/ugauth` (`check_walls`, `host/bin/ug-setup`).

## Not covered, accepted by name

- The owner through sudo reaches everything. This stops slips and any program that runs as the owner, not the owner on purpose.
- An omp that the owner downloads, or a copy of Tern's, still starts. It has no login and no bearer. It still finds the keyless providers that omp adds by itself, such as `apple/on-device` (`0012-pinned-omp-and-setup.md`, "Amendment 2026-11-03: the raw omp's keyless providers"), unless the owner's `~/.omp/agent/config.yml` turns them off.
- An API key is billed per call. A stored OAuth login beats a broker-stored API key of the same provider (omp `docs/models.md`, lines 689 to 699, read 2026-11-08), so the key serves calls when the login cannot. [inference, not run] That includes a usage limit of the subscription. A taken-over session can then spend money; the owner sets a spending cap at the provider. This changes a decision that assumed OAuth only (`0013-agent-box.md`, "No spend limit at the model door").
